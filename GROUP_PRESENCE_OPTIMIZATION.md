# Exact group-domain and presence proofs

[EinFold](https://github.com/xqlsystems/einfold), the tensor optimizer for
SQL, removes two redundant group-mask computations in its compact executor.

Dependent integer GPU grouping already requires a declared, validated finite
key domain. It now reuses the indexed-join domain-subset proof when grouping
into that domain. Scatter accumulation is unchanged; only the redundant
device-dependent found mask becomes known true. This assumes a validated
domain, not that arbitrary integer values fit an input shape.

A present, nonnullable grouped UNION ALL branch with independent key axes
and exactly matching complete ordered output coordinate domains proves
group existence and non-NULL contribution coverage. Other branches can add
duplicates, NULLs or partial values without invalidating that proof.
Numerical branch accumulation remains unchanged. Reordered/partial domains,
correlated key axes and branches without full valid coverage keep the
original flag calculation. Empty coordinate domains retain their empty
output shape. Set `EINFOLD_DENSE_GROUP_PROOFS=0` before execution to compare
the original calculations; these proofs are enabled by default.

This matters for differentiated SQL: sparse target-gradient contributions
can join complete gradient branches, making the combined presence known
even though the sparse branch depends on runtime integer labels. Avoiding
its mask propagation reduces later work without removing SQL NULL handling.

Thirty-two seeded cases compare schemas, values, row counts, integer counts
and NULL flags with [DataFusion](https://datafusion.apache.org/), the SQL
engine, with proofs enabled and disabled. They cover complete and partial
domains, reordering, empty inputs, duplicate contributions, dynamic filters
and nullable columns. Downstream GPU training additionally checks declared
index domains, raw gradients, state updates and independent model controls.

On Apple M5 Ultra, a matched 100-update no-dropout Shakespeare training
comparison in [xarray-sql](https://github.com/xqlsystems/xarray-sql), the
labeled-array SQL host, measured **48.71 → 38.96 ms** warm updates, **1.250×**,
from these proofs alone. The 10,745,088-parameter model uses float32,
[MLX](https://github.com/ml-explore/mlx) 0.32.4, Apple's GPU array framework,
full validation, frozen compiled state, batch 12/context 256 and derivatives
generated by [ddx](https://github.com/xqlsystems/ddx), the SQL differentiator. Input preparation,
evaluation, logging, compilation and checkpoint I/O are outside warm timing.
All 33 final weights and moments of [AdamW](https://arxiv.org/abs/1711.05101),
the decoupled-weight-decay optimizer, match the reference within 3e-5;
maximum absolute difference is below 2.4e-7. These are serial observations,
not confidence intervals or whole-application timings. The downstream
`GPU_ATTENTION_LOWERING.md` report records the broader ablations and limits.
